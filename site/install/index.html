Integration guide

The same core API works with a script tag, JavaScript modules and React applications. Mount one instance per document.

Prepared package: @widgets/accessibility (not yet published). The browser global is Accessiblit. The redesigned demo uses the local build. The pinned CDN example loads the previous published package; the new organization package and React integrations are tested from a locally packed tarball, not from the registry.

CDN script tag

Place the script before the init call. The library exposes the Accessiblit global and can wait for the document body. 

<script src="https://cdn.jsdelivr.net/npm/@qasimfida/accessibility-widget@0.1.1/dist/accessiblit.min.js" integrity="sha384-92p98tW9X5RIeEH3DgJaTj4mWx29zz9C5jAH1Jd+AeCQUHivVa6CYiWAkYtQ3JC3" crossorigin="anonymous"></script>
<script>
  Accessiblit.init();
</script>

npm and ESM

After the organization package is published, install it and import the module from your application entry.

The npm examples below are prepared for the new organization package. Until it is published, use a locally packed tarball. The CDN example above remains the previous published package and does not include the redesigned panel. 

npm install @widgets/accessibility@0.1.1
import { init } from '@widgets/accessibility';

const widget = init({ position: 'bottom-left' });
// Call widget.destroy() when removing this integration.

React

React is an optional peer dependency, version 17 or newer. An effect keeps DOM work on the client and cleans up the instance it created, including under StrictMode. 

npm install @widgets/accessibility@0.1.1 react react-dom
import { useEffect } from 'react';
import { init } from '@widgets/accessibility';

export default function Accessibility() {
  useEffect(() => {
    const widget = init({ position: 'bottom-right' });
    return () => widget.destroy();
  }, []);
  return null;
}

Next.js App Router

Create a client component and render it from your layout. The effect owns and cleans up the widget instance. React stays in your application rather than the core browser bundle. 

'use client';

import { useEffect } from 'react';
import { init } from '@widgets/accessibility';

export default function Accessibility() {
  useEffect(() => {
    const widget = init({ position: 'bottom-right' });
    return () => widget.destroy();
  }, []);
  return null;
}

HTML and plain JavaScript

Use the CDN example above for the previous published release, or self-host this build. Place the local IIFE before your own initialization file. Load both with defer to preserve their order. 

<script defer src="/assets/accessiblit.min.js"></script>
<script defer src="/assets/accessibility-init.js"></script>

In accessibility-init.js:

const widget = Accessiblit.init({ position: 'bottom-right' });
// Before removing this integration: widget.destroy();

Vue 3

Mount this component once in your application shell. Lifecycle hooks keep initialization in the browser and clean up the owned instance, including with server rendering. 

<script setup lang="ts">
import { onMounted, onBeforeUnmount } from 'vue';
import { init, type AccessiblitInstance } from '@widgets/accessibility';
let widget: AccessiblitInstance | undefined;
onMounted(() => { widget = init(); });
onBeforeUnmount(() => { widget?.destroy(); });
</script>
<template><span hidden></span></template>

Angular 17+

Render this standalone component once in the root template. afterNextRender runs only in the browser; DestroyRef releases the instance when Angular removes the component. 

import { Component, DestroyRef, afterNextRender, inject } from '@angular/core';
import { init } from '@widgets/accessibility';

@Component({ selector: 'app-accessibility', standalone: true, template: '' })
export class AccessibilityComponent {
  private readonly destroyRef = inject(DestroyRef);
  constructor() {
    afterNextRender(() => {
      const widget = init();
      this.destroyRef.onDestroy(() => widget.destroy());
    });
  }
}

WordPress

This is a manual theme integration, not a WordPress plugin. Copy the IIFE to your child theme's assets folder and create accessibility-init.js using the plain JavaScript example above. Enqueue both from the child theme's functions.php; the dependency preserves initialization order. 

add_action('wp_enqueue_scripts', function () {
    $assets = get_stylesheet_directory_uri() . '/assets/';
    wp_enqueue_script('accessiblit', $assets . 'accessiblit.min.js', array(), '0.1.1', true);
    wp_enqueue_script('accessiblit-init', $assets . 'accessibility-init.js', array('accessiblit'), '0.1.1', true);
});

Footer loading can show the original page before persisted preferences apply. For strict CSP, allow your local assets and pass the response's nonce to init. Do not paste credentials into theme files.

Shopify

This is a manual Online Store theme integration, not an App Store app. In a duplicate theme, upload accessiblit.min.js and accessibility-init.js to Assets. Use the initialization file shown above. Add these tags once in layout/theme.liquid before the closing body tag, preview and test before publishing the theme. 

<script defer src="{{ 'accessiblit.min.js' | asset_url }}"></script>
<script defer src="{{ 'accessibility-init.js' | asset_url }}"></script>

The theme serves these assets through Shopify's own asset infrastructure. The widget makes no requests after loading. Checkout and embedded third-party frames have separate platform restrictions. Footer initialization does not guarantee flash-free restoration.

Self-hosted file

Copy dist/accessiblit.min.js from your built package to your own static assets. This example assumes you serve it at /vendor/accessiblit.min.js. A strict CSP must also authorise your script and supply an owner nonce when fallback styles need one. 

<script src="/vendor/accessiblit.min.js"></script>
<script>
  Accessiblit.init({ position: 'bottom-right' });
</script>

Private distribution

Tarball

Build and pack the source, then give the resulting .tgz file to your consuming project. Adjust the path to the file you received. 

npm run build
npm pack
# In the consuming project:
npm install ./path/to/widgets-accessibility-0.1.1.tgz

Git source

For private distribution, use these build-and-pack steps with your team’s private mirror; the public repository below is a reproducible example. A Git checkout contains source rather than committed dist files. Build it before packing; do not assume a bare Git dependency includes built artifacts. 

git clone https://github.com/qasimfida/accessiblit.git
cd accessiblit
git checkout 03037d0
npm ci
npm run build
npm pack

Private registry

Your team can distribute the package through its registry and normal credential management. Replace the example registry URL with yours; no credentials belong in page source or these snippets. 

npm install @widgets/accessibility --registry=https://registry.example.invalid

Personalisation supports visitor choice. It does not make a site conformant by itself.
